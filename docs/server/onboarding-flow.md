# Onboarding Flow

## Purpose

The Discord is the gateway. Its job is simple: welcome new people, explain what Aeloria is, guide them toward useful work, and make them feel like they are joining a world with a purpose.

## First principle

New members should not be left to wander the server without a path.

If the server is to recruit builders, lore writers, testers, artists, and worldmakers, then the flow must answer three questions immediately:

1. What is this project?
2. What is there to do here?
3. How do I join in?

## Recommended onboarding sequence

### Step 1 — Welcome channel

The first message should explain the project in plain language that still sounds like Aeloria.

Suggested framing:

- Aeloria is a world-first Minecraft project.
- It is built around lore, territory, and meaningful exploration.
- The Discord is where people recruit, coordinate, and shape the world.
- The Minecraft server is where the world becomes real.
- The project is still in preparation and is looking for builders, lore contributors, worldbuilders, and community members.

### Step 2 — Roles and identity

Members should be asked to choose a role soon after joining.

Suggested roles:

- Builder
- Lore Writer
- Scribe
- Artist
- Moderator
- Roleplayer
- Explorer
- Server Tester
- Community Helper
- Staff / Leadership

The purpose is not decoration. It is to sort contribution and attention.

### Step 3 — Introductions

Members should be directed to an `#introductions` channel where they say:

- who they are
- what they want to contribute
- what part of the world interests them most
- whether they are here for lore, building, testing, world design, or community support

This is the first real recruitment step. Do not leave it vague.

### Step 4 — Lore and world access

The onboarding flow should direct members into the lore and world channels:

- `#what-is-aeloria`
- `#the-promise`
- `#territory-map`
- `#lore-library`

This helps new people understand the project before they start offering ideas.

### Step 5 — Contribution path

The server should direct new people toward one of these things:

- build a territory
- write lore, books, or world fragments
- map or document a location
- help test the world
- participate in the community and event planning
- support the server setup and launch path

No one should join and be asked, vaguely, to “help out.” The project needs tasks.

## Staff guidance

The first staff members need a simple rule:

> Make the project feel alive without making it feel closed.

New members should feel invited. They should also feel like there is structure, and that the world is being built intentionally.

## Recommended member journey

1. Join
2. Read the welcome and rules
3. Pick a role
4. Introduce themselves
5. Read the lore and world map
6. Choose a contribution lane
7. Receive a first task from the proper lead

## Public-facing principle

If the Discord is for recruitment, then it must be transparent. People should know:

- what the project is
- what the timeline is
- what kind of contributions are needed
- where to begin
- who to ask

If a person cannot tell, within a few minutes, what the project is and how to help, the recruitment flow has failed.
